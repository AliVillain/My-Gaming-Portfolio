# Adding game videos and screenshots

1. Open `assets/games` and find the folder named after your game. Its `README.txt` includes the game link.
2. Copy videos or screenshots into that folder. Any filename works, including spaces. Subfolders also work.
3. Double-click `START-SITE.cmd`, then open http://127.0.0.1:8096/games.html in your browser. Node.js must be installed (it is installed on this computer).
4. Drive into the game box or select the game under **Browse all games**. The server rescans the folder each time you open the panel. If a panel is already open, close and reopen it after adding media.

Supported videos: `.mp4`, `.webm`, `.m4v`, `.ogv`, `.ogg`. Use browser-compatible encoding; MP4 with H.264 video and AAC audio is a practical choice. Supported screenshots: `.png`, `.jpg`, `.jpeg`, `.webp`, `.gif`, `.avif`. Files display in alphabetical order; prefixes such as `01-` and `02-` control ordering. Unsupported files are ignored, and failed media is hidden.

Empty folders show only the game or project link. Videos do not autoplay. Closing the panel stops playback.

## Publishing to GitHub Pages

Run `UPDATE-MEDIA.cmd` after adding, removing, or renaming files. Then upload/commit the updated `games-data.js`, `media-manifest.json`, and game folders along with the site. This command does not publish anything by itself.

GitHub Pages cannot scan directories at runtime. Its displayed media is the snapshot generated by this command. Directly opening `games.html` also uses this snapshot; the local launcher provides automatic scanning.

## Links and game names

Edit `games.json` to change names, store URLs, or external `videoLinks`. Run `UPDATE-MEDIA.cmd` afterward. Do not edit generated `games-data.js` or `media-manifest.json` directly.

Each game has a stable `id` and a matching `folder`. To add a new game, add an entry to `games.json` with `id`, `name`, `url`, `category: "game"`, and `folder: "assets/games/your-game-name"`; create that folder and run the update command. Reload the page for catalog changes.

The supplied Word document is retained as extracted links in `document-links.json`. Existing portfolio games remain in the catalog, and Google Play duplicates were matched by package ID. Some store pages were unavailable, so their existing portfolio titles were retained. The VR Cricket title comes from its supplied URL.

The five older video/demo links appear separately in **Browse all games → Older demos**. They have their own folders too. Their relationship to a particular store game was not confirmed, so they were not assigned to one. LinkedIn posts and Google Drive folders open externally; place an actual video file in a folder for in-page playback.

## Checks

Run `node tools/check-media.cjs` to check folder scanning, empty media, all supplied links, and game box entry/re-entry. No extra packages are needed.
